為什麼 DeepSRT 沒有伺服器

2026 年 7 月 · DeepSRT 開發筆記

看過 DeepSRT v1 架構圖的人都會問一個合理的問題：「你們有完整的雲端後端、有一整池輪替代理去抓 YouTube 字幕——好好的服務，為什麼 v2 全部丟掉，改成一個 Mac App？」

短版答案：因為使用者自己的 IP 是比任何代理池都好的基礎設施。長版答案如下。

貓抓老鼠

v1 的做法和所有「幫使用者抓 YouTube 資料」的服務一樣：使用者的請求進到我們的伺服器，伺服器去 YouTube 抓字幕，回傳。問題是 YouTube 對資料中心 IP 的容忍度是結構性的低：一個 IP 服務一千個使用者，它的請求模式就是機器人。被擋是常態，不是意外。

所以你開始建代理池。然後代理也會被擋，所以你需要健康檢查、輪替、換供應商。我們後端有一半的程式碼在做這件事——不是產品功能，是維持管道暢通。每一層 workaround 都是在跟平台的風控玩貓抓老鼠，而貓永遠比你大。

集中式抓取讓所有使用者共享同一個命運。一個出口 IP 被限流，所有人一起壞。你的可靠性上限，就是你最像機器人的那一刻。

把抓取還給使用者

v2 把整個管線反過來：App 在你的 Mac 上，用你家的 IP、以一個正常人類的觀看量，直接跟 YouTube 的公開字幕端點拿資料。對 YouTube 來說，你就是你——一個看影片的人，不是一個代理池。風控問題不是被解決了，是被架構消除了。

AI 摘要也一樣：你自己的 Google Gemini 金鑰（BYOK），存在 macOS Keychain，App 直接呼叫 Gemini API。你看了什麼影片、生成了什麼摘要，不經過任何第三方伺服器——包括我們的，因為我們沒有伺服器。

隱私通常是一段政策文字：「我們承諾不看你的資料。」DeepSRT 的版本是一個架構性質：「我們想看也沒有地方看。」

成本誠實

沒有伺服器帳單，就沒有要轉嫁給你的固定成本，也就不需要用訂閱制來養基礎設施。你付一次 App 的錢；AI 的部分，Gemini 的免費額度對絕大多數人的觀看量綽綽有餘。我們不在中間賺差價，也不用擔心哪天 API 漲價要偷偷調整方案。

誠實的邊界

BYOK 有真實的門檻：你要自己去申請一把 Gemini 金鑰（免費，但多一個步驟）。這是「零伺服器」換來的代價，我們認為值得，但它確實不是零摩擦。

本機抓取也不是免疫的。我們自己在開發時就踩過：短時間打太多字幕請求，一樣吃 YouTube 的 429。差別在於處理方式——因為量是一個人的量，快取（記憶體＋磁碟）、合併請求、退避重試就足以讓它幾乎不發生；而在集中式架構裡，這是一場永遠燒不完的火。

還有：目前只有 macOS。這個架構的代價是它綁定在「你自己的機器」上——沒有機器，就沒有 DeepSRT。

門沒有上鎖

App 內建一個本機 API（127.0.0.1），Chrome 擴充功能靠它變成一個薄客戶端——所有邏輯都在 App 裡。這個輕量版擴充功能即將開源；私有 MCP 支援也在路上，讓你的 AI agent 直接跟 DeepSRT 對話。

架構裡沒有任何東西阻止更多客戶端。沒有伺服器不代表封閉——恰恰相反：因為一切都在你的機器上，一切都能被你的工具使用。

順帶一提：常駐的本機 API 是 native app 才做得到的事——瀏覽器擴充功能的背景程序，隨時會被平台回收。為什麼 DeepSRT 最後落腳在 Mac App，是下一篇的主題。
